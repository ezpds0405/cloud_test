# 쓰레드 육아 이벤트 알림 봇: 최저 비용(0원) 설계안

> 상태: 설계 초안 (구현 전)
> 기준 문서: `threads-baby-event-digest-design.md` (10장 개선안 포함)
> 목표: **월 고정비 0원.** 유료 요소는 기본에서 빼고, 필요하면 나중에 켤 수 있는 선택 옵션으로만 둔다.

---

## 1. 비용 구조 비교

| 구성 요소 | 기존안 | 0원안 | 비고 |
|---|---|---|---|
| 게시글 수집 | Threads API | Threads API | 무료 (검수 필요) |
| 이벤트 판별·정보 정리 | Claude API (월 약 1,700원) | **규칙 기반(키워드·정규식·링크 주소)** | 무료 |
| 공지 이미지 판독 | Claude 이미지 판독 | **Tesseract OCR(오픈소스, 한국어 데이터)** | 무료, 정확도는 낮음 |
| 실행 환경 | GitHub Actions | GitHub Actions (비공개 저장소) | 월 2,000분 무료, 예상 사용 약 360분 |
| 상태 저장 | data 브랜치 | 저장소 내 JSON 파일 1개 | 무료 |
| 알림 | 텔레그램 | 텔레그램 | 무료 |
| **합계** | 월 약 1,700원 | **0원** | |

0원안의 대가는 **정확도**다. 이미지로만 된 공지, "이번 주 목요일 저녁" 같은 애매한 날짜는 놓치거나 "확인 필요"로 빠지는 비율이 높아진다. 이를 줄이기 위해 아래 3가지를 쓴다.

1. 링크 주소로 플랫폼 판별 (가장 정확하고 공짜)
2. 사용자 피드백으로 규칙을 계속 보강
3. 애매한 글만 사람이 1초 보고 넘기도록 "확인 필요" 칸을 짧게 유지

---

## 2. 처리 흐름

```
[2시간마다 · GitHub Actions]
 ① 텔레그램 받은 메시지 확인 (공유 링크, 피드백 명령)
 ② 쓰레드 키워드 검색 (since=마지막 실행 시각 → 새 글만)
 ③ 이미 본 글 제외 (post_id)
 ④ 규칙 필터: 육아 단어 AND (이벤트 | 라이브 | 행사 단어), 제외 단어·차단 계정 적용
 ⑤ 정보 추출 (규칙): 유형, 플랫폼, 날짜·시각, 혜택, 링크
    └ 본문에 날짜가 없고 이미지가 있으면 → OCR 후 다시 추출
 ⑥ 같은 행사 묶기: (계정 또는 브랜드, 유형, 날짜)
 ⑦ state.json 저장 · 3시간 내 라방이면 즉시 알림
[08:00 / 20:00 KST]
 ⑧ 브리핑 전송 (유형별 상위 5개 + 확인 필요)
```

수집과 브리핑을 같은 작업으로 돌리고, 실행 시각이 브리핑 시각대면 ⑧까지 수행한다. 작업 1회 약 1분 × 하루 12회 × 30일 ≈ **월 360분** (무료 2,000분 이내).

## 3. 규칙 기반 추출 상세

### 3.1 유형 판별 (점수제)

| 유형 | 단어 (가중치) |
|---|---|
| 라이브 | `라방`, `라이브`, `쇼핑라이브`, `생방송`, `방송 알림` (+2) / `시청`, `알림설정` (+1) |
| 체험단·이벤트 | `체험단`, `모집`, `응모`, `당첨`, `댓글이벤트`, `리그램`, `서포터즈` (+2) / `추첨`, `발표` (+1) |
| 오프라인 행사 | `베이비페어`, `박람회`, `팝업`, `코엑스`, `킨텍스`, `벡스코`, `세텍`, `aT센터` (+2) / `사전등록`, `무료입장` (+1) |
| 육아 (필수 조건) | `아기`, `신생아`, `유아`, `육아`, `베이비`, `기저귀`, `젖병`, `이유식`, `분유`, `유모차`, `카시트`, `아기띠`, `물티슈` |

- 육아 단어가 없으면 제외. 가장 높은 점수의 유형으로 분류, 점수 2 미만이면 제외
- 제외 단어: `중고`, `구해요`, `삽니다`, `나눔 받아요` (+ 공구 비활성 시 `공구`, `공동구매`)

### 3.2 플랫폼 판별 (링크 주소 우선)

| 링크/단어 | 플랫폼 |
|---|---|
| `shoppinglive.naver.com`, `naver.me` + 라이브 단어, `네이버 쇼핑라이브` | 네이버 쇼핑라이브 |
| `shoppinglive.kakao.com`, `카카오 쇼핑라이브`, `톡딜라이브` | 카카오 쇼핑라이브 |
| `coupang.com` + 라이브 단어, `쿠팡라이브` | 쿠팡 라이브 |
| `grip.show`, `그립` | 그립 |
| `forms.gle`, `docs.google.com/forms`, `form.naver.com` | 신청폼 (체험단) |
| `instagram.com` | 인스타그램 |

단축 URL(`bit.ly` 등)은 HTTP HEAD 요청으로 최종 주소를 확인한 뒤 판별 (무료).

### 3.3 날짜·시각 추출 (정규식, 게시 시각 기준)

| 표현 | 해석 |
|---|---|
| `11/5`, `11.5`, `11월 5일` | 해당 날짜 (게시일보다 이전이면 다음 해) |
| `(수)`, `수요일` 단독 | 게시일 이후 가장 가까운 수요일 |
| `오늘`, `내일`, `모레`, `이번 주 X요일`, `다음 주 X요일` | 게시일 기준 계산 |
| `20:00`, `20시`, `오후 8시`, `저녁 8시`, `밤 9시` | 시각 (`저녁·밤·오후` → +12시간) |
| `~11/10`, `11/10까지`, `마감 11/10` | 마감일 |
| `11/13~16`, `11.13(목)~11.16(일)` | 기간 |

- 날짜와 요일이 같이 있는데 서로 맞지 않으면 → 확인 필요
- 날짜를 못 찾으면 → 확인 필요 (버리지 않음)

### 3.4 혜택 추출

- `최대 \d+%`, `\d+% 할인`, `\d+만원`, `증정`, `사은품`, `1+1`, `무료배송` 이 들어간 문장을 최대 2개 뽑아 그대로 표시

### 3.5 이미지 OCR (무료)

- GitHub Actions 실행 시 `tesseract-ocr`, `tesseract-ocr-kor` 설치 (`apt-get`, 약 20초)
- **본문에서 날짜를 못 찾았고 이미지가 있을 때만** OCR 수행 → 실행 시간 절약
- OCR 결과에 3.3 규칙을 다시 적용. 한국어 OCR은 꾸민 글씨체에서 정확도가 낮으므로 OCR에서 얻은 날짜는 "📷 이미지에서 읽음" 표시

## 4. 저장 방식 (state.json)

```json
{
  "last_run": "2026-11-05T08:00:00+09:00",
  "seen_post_ids": ["…최근 30일…"],
  "sent_events": {"oobaby|live|2026-11-05": "내용해시"},
  "blocked_accounts": ["@spam_account"],
  "extra_exclude_words": ["공구"],
  "telegram_update_offset": 123456789
}
```

- 실행이 끝나면 이 파일만 저장소에 커밋 (봇 전용 브랜치 `state`)
- 30일 지난 기록은 자동 삭제해 파일을 작게 유지
- 커밋이 계속 생기므로 저장소가 "활동 중"으로 유지되어 예약 실행이 멈출 위험도 줄어듦

## 5. 정확도를 0원으로 올리는 방법: 피드백

텔레그램 봇에 답장으로 명령을 보내면 다음 실행 때 반영한다.

| 명령 | 동작 |
|---|---|
| (쓰레드 글 링크 붙여넣기) | 수동 공유 모드: 그 글을 정리해 다음 브리핑에 포함 |
| `/차단 @계정` | 해당 계정 글 제외 |
| `/제외 단어` | 제외 단어 추가 |
| `/추가 단어` | 검색·판별 단어 추가 |
| `/전체` | 이번 브리핑 전체 목록 보기 (다음 실행 때 전송) |

명령은 실행 때마다 `getUpdates`로 한꺼번에 읽으므로 상시 서버가 필요 없다(응답은 최대 2시간 늦음).

## 6. 쿼터·실행 시간 절약 규칙

- 검색은 `since`로 새 글만 요청
- 키워드는 조합형 8~12개로 제한 (예: `육아 체험단`, `기저귀 라방`, `베이비페어`)
- 키워드별 "최근 4주 적중 건수"를 state에 기록해 0건 키워드는 주 1회만 검색
- GitHub Actions 작업은 1개 job으로 구성 (job마다 분 단위 올림 과금되므로 쪼개지 않음)
- Python 의존성 캐시(`actions/setup-python`의 pip 캐시)로 설치 시간 단축

## 7. 나중에 켤 수 있는 선택 옵션 (유료, 기본 꺼짐)

| 옵션 | 비용 | 효과 |
|---|---|---|
| "확인 필요" 항목만 Claude Haiku 5.5로 재정리 | 하루 5~10건 기준 월 수백 원 이하 | 이미지·애매한 날짜 정확도 개선 |
| 위 작업을 Message Batches API로 처리 | 위의 50% | 즉시성이 필요 없는 브리핑용에 적합 |
| Anthropic Console 월 사용 한도 설정 | — | 예상 외 과금 방지 |

설정 파일에서 `llm_fallback: false`(기본값)로 둔다.
