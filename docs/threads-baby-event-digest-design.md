# 쓰레드 육아용품 이벤트·라이브 알림 봇 검토안

> 상태: 검토/설계 초안 (구현 전)
> 범위 변경: **자동응모는 하지 않음.** Threads에 올라온 육아용품 이벤트와 라이브 행사를 모아 정리한 뒤 텔레그램으로 보내기만 한다.
> 이전 설계안(`threads-baby-event-bot-design.md`)에서 응모 실행(Executor) 부분을 빼고, 라이브 행사 수집을 추가했다.

---

## 1. 검토 결론 요약

| 항목 | 판단 |
|---|---|
| 실현 가능성 | **가능.** 단, Threads 공개 게시글 검색 권한(`threads_keyword_search`)의 Meta 앱 검수 통과가 전제 |
| 약관 위험 | 낮음. 공식 API로 읽기만 하고, 게시·팔로우·댓글 같은 계정 활동을 하지 않음 |
| 필요 권한 | `threads_basic`, `threads_keyword_search` (+ 선택: `threads_profile_discovery`) — 게시 권한 불필요 |
| 운영 형태 | 상시 서버 불필요. **정해진 시간에 실행되는 배치 작업(cron)**으로 충분 → GitHub Actions 무료 범위에서 운영 가능 |
| 월 비용 | LLM 분류 비용만 발생, 하루 수십~수백 건 기준 월 몇 천 원 이하 예상 (실측 필요) |
| 최대 위험 | ① 앱 검수 반려 ② 키워드 검색 쿼터 ③ 라이브 시작 시각이 이미지에만 있는 경우 추출 정확도 |

자동응모 대비 장점: 답글 게시·버튼 승인이 없으므로 텔레그램 쪽은 **메시지 전송만** 하면 되고, 콜백을 받을 상시 서버가 필요 없다.

---

## 2. 수집 대상 정의

| 유형 | 예시 | 핵심 추출 항목 |
|---|---|---|
| **체험단·댓글 이벤트** | 체험단 모집, 댓글/리그램 이벤트, 서포터즈 | 브랜드, 제품, 대상 월령, 당첨 인원, 마감일, 참여 방법 |
| **라이브 커머스** | 네이버 쇼핑라이브, 카카오 쇼핑라이브, 쿠팡 라이브, 그립, 인스타/쓰레드 라이브 | **방송 시작 일시**, 플랫폼, 브랜드, 할인율·사은품·라방 한정 혜택, 알림신청 링크 |
| **오프라인 행사** | 베이비페어, 브랜드 팝업, 체험존 | 장소, 기간, 사전등록/무료입장 여부 |
| **할인·특가** (선택) | 타임딜, 공구 오픈 | 기간, 할인 내용 |

공구(공동구매) 홍보 글은 양이 많고 광고성이 짙으므로 **기본은 제외**하고 설정으로 켤 수 있게 한다.

---

## 3. 전체 흐름

```
[GitHub Actions cron]  (예: 매일 08:00 / 12:00 / 20:00 KST)
        │
        ▼
1. Collector   ── Threads keyword_search (RECENT, since=마지막 실행 시각)
        │
        ▼
2. Pre-filter  ── 키워드 규칙: (이벤트|라이브|행사 단어) AND (육아 단어)
        │
        ▼
3. Extractor   ── Claude API로 유형 분류 + 구조화 JSON 추출 (이미지 공지도 판독)
        │
        ▼
4. Dedup/Merge ── 같은 행사의 재게시·여러 계정 홍보를 하나로 묶음
        │
        ▼
5. Digest      ── 유형별·마감/시작 임박순 정리 → 텔레그램 전송
        │
        ▼
6. State save  ── 처리한 게시글 ID, 보낸 행사 목록 저장 (다음 실행 때 중복 방지)
```

---

## 4. 단계별 상세

### 4.1 Collector

- API: `GET https://graph.threads.net/v1.0/keyword_search`
  - `q`, `search_type=RECENT`, `since`(마지막 실행 시각), `fields=id,text,permalink,timestamp,username,media_type,media_url`
- 키워드(설정 파일 `config.yaml`):
  - 이벤트: `육아 체험단`, `아기 체험단`, `육아템 이벤트`, `기저귀 이벤트`, `이유식 체험단`, `유아 댓글이벤트`
  - 라이브: `육아 라방`, `유아 라이브`, `기저귀 라방`, `베이비 쇼핑라이브`, `육아템 라이브`, `라방 알림`
  - 행사: `베이비페어`, `육아 박람회`, `유아용품 팝업`
- 검색 쿼터가 있으므로 **키워드 수 × 하루 실행 횟수 ≤ 쿼터**가 되도록 조정. 조합 키워드를 쓰면 적은 호출로도 정확도가 높다. 정확한 쿼터 수치는 착수 시 공식 문서로 확인.
- (선택) 자주 행사를 하는 브랜드 계정 목록을 등록해 두고 프로필 조회 API(`threads_profile_discovery`, 지원 범위 착수 시 확인)로 해당 계정의 최근 글을 함께 확인 → 키워드 검색에서 놓친 글 보완.

### 4.2 Pre-filter (무료, 빠름)

- 이벤트/라이브/행사 단어와 육아 단어가 둘 다 있어야 통과
- 제외 단어: `중고`, `나눔 받아요`, `구해요`, 공구 비활성 시 `공구`
- 목표: LLM에 넘기는 양을 줄여 비용을 아낌

### 4.3 Extractor (Claude API)

- 모델: `claude-haiku-5-5` (분류·추출용 저가 모델로 충분). 공지가 이미지인 글은 `media_url` 이미지를 함께 전달
- 출력 예:

```json
{
  "type": "live",              // trial_event | live | offline | deal | not_relevant
  "brand": "OO베이비",
  "title": "OO베이비 겨울 속싸개 런칭 라방",
  "platform": "네이버 쇼핑라이브",
  "start_at": "2026-11-05T20:00:00+09:00",
  "end_at": null,
  "deadline": null,
  "target_child_age": {"min_months": 0, "max_months": 12},
  "benefits": ["최대 40% 할인", "구매 전원 손수건 증정"],
  "how_to_join": "방송 알림받기 후 시청",
  "link": "https://...",
  "confidence": 0.88
}
```

- 날짜 표현("이번 주 목요일 저녁 8시", "11/5(수)")은 **게시 시각 기준**으로 해석하도록 프롬프트에 게시 시각과 KST를 명시
- `confidence < 0.6` 또는 날짜를 못 찾은 경우 "확인 필요" 섹션으로 분리

### 4.4 Dedup / Merge

- 같은 게시글: `post_id`로 제외
- 같은 행사의 여러 홍보 글: `(brand, type, start_at 또는 deadline 날짜)`가 같으면 하나로 묶고 출처 링크를 여러 개 표시
- 이미 보낸 행사: 내용이 바뀌지 않았으면 다시 보내지 않음. 단, 라이브는 **시작 당일 아침에 한 번 더 리마인드**

### 4.5 Digest — 텔레그램 메시지

- 전송: Telegram Bot API `sendMessage` (`parse_mode=HTML`) — HTML 모드가 MarkdownV2보다 특수문자 이스케이프 문제가 적음
- 제약: 메시지 1건 최대 4,096자 → 길면 유형별로 나눠 여러 건 전송. 링크 미리보기는 끄기(`link_preview_options.is_disabled=true`)
- 메시지 예시:

```
🍼 육아 이벤트 브리핑 · 11/3(화) 저녁

📺 라이브 (3)
• 11/4(수) 20:00 · OO베이비 속싸개 런칭 라방 — 네이버 쇼핑라이브
  최대 40%↓, 구매 전원 손수건 · [원문] [방송]
• 11/5(목) 11:00 · △△ 기저귀 라방 — 카카오 쇼핑라이브 · [원문]

🎁 체험단·이벤트 (5)  ※ 마감 임박순
• ~11/6 · □□ 이유식 체험단 10명 (6~12개월) · [원문]
• ~11/9 · ◇◇ 아기띠 댓글이벤트 3명 · [원문]

📍 오프라인 행사 (1)
• 11/13~16 · 코엑스 베이비페어 (사전등록 무료입장) · [원문]

❓ 확인 필요 (2)
• 날짜 불명확: ☆☆ 젖병 이벤트 · [원문]
```

- 전송 시점:
  - **정기 브리핑:** 하루 1~2회 (예: 08:00, 20:00 KST)
  - **긴급 알림(선택):** 시작 3시간 이내 라이브, 마감 24시간 이내 이벤트가 새로 발견되면 즉시 별도 메시지
- 필터 설정(`config.yaml`): 아이 월령, 관심 카테고리, 공구 포함 여부, 플랫폼 화이트리스트

### 4.6 State 저장

GitHub Actions는 실행마다 환경이 초기화되므로 상태 저장이 필요하다.

| 방법 | 장점 | 단점 |
|---|---|---|
| **상태 파일(JSON/SQLite)을 저장소의 별도 `data` 브랜치에 커밋** (권장) | 무료, 이력 확인 가능 | 커밋이 계속 쌓임(주기적 정리) |
| Actions cache | 설정 간단 | 7일 미사용 시 삭제, 보장 안 됨 |
| 소형 VPS + SQLite | 가장 단순·안정 | 월 비용 발생 |

저장 내용: 마지막 실행 시각, 처리한 `post_id`(최근 30일), 보낸 행사 키와 내용 해시.

## 5. 기술 스택

- Python 3.12, `httpx`, `pydantic`(추출 결과 검증), `anthropic` SDK, `PyYAML`
- 텔레그램은 라이브러리 없이 `httpx`로 Bot API 직접 호출 (전송만 하므로 충분)
- 실행: GitHub Actions `schedule` (cron은 **UTC 기준** → KST 08:00 = `0 23 * * *`)
- 시크릿(GitHub Actions Secrets): `THREADS_ACCESS_TOKEN`, `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
- Threads 장기 토큰은 60일 만료 → **주 1회 토큰 갱신 작업** 추가. 갱신 실패 시 텔레그램으로 경고

```
bot/
  config.yaml        # 키워드, 필터, 전송 시각
  main.py            # 전체 파이프라인 실행
  threads_client.py  # 검색 API, 쿼터·토큰 관리
  prefilter.py
  extractor.py       # Claude 호출 + pydantic 검증
  dedup.py
  digest.py          # 메시지 포맷, 4096자 분할
  telegram.py
  state.py
tests/               # 샘플 게시글 픽스처로 추출·중복제거·포맷 테스트
.github/workflows/digest.yml
```

## 6. 사전 준비

1. **텔레그램:** BotFather에서 봇 생성 → 토큰 발급 → 봇에게 메시지 1회 전송 후 `getUpdates`로 `chat_id` 확인. 가족과 같이 받으려면 그룹/채널을 만들고 봇 추가
2. **Meta:** 개발자 앱 생성 → Threads API 유즈케이스 → 본인 계정 테스터 등록 → 토큰 발급 → **`threads_keyword_search` 앱 검수 신청** (가장 오래 걸리므로 최우선)
3. **Anthropic:** API 키 발급

## 7. 단계별 계획

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| Phase 0 | 텔레그램 봇·Meta 앱·토큰 준비, 검수 신청 | 테스트 메시지 수신, 검색 API 호출 성공 |
| Phase 1 | 수집 → 규칙 필터 → 추출 → 텔레그램 브리핑 (상태 저장 포함) | 하루 2회 브리핑 자동 수신 |
| Phase 2 | 중복 묶기, 라이브 당일 리마인드, 긴급 알림 | 같은 행사가 한 줄로 묶이고 라방 당일 알림 수신 |
| Phase 3 | 필터 개인화(월령·카테고리), 확인 필요 항목 정확도 개선 | 관련 없는 항목 비율 측정·감소 |

검수 승인 전에도 **샘플 게시글 픽스처로 Phase 1의 추출·포맷·전송은 미리 개발·테스트 가능**하다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 앱 검수 반려 → 공개 글 검색 불가 | 브랜드 계정 목록 기반 조회(프로필 조회 API 가능 여부 확인), 또는 사용자가 앱에서 본 글 링크를 봇에 보내면 정리만 해 주는 수동 모드 |
| 검색 쿼터 부족 | 조합 키워드로 수 축소, 실행 횟수 조정, 키워드별 적중률을 기록해 낮은 키워드 제거 |
| 라방 일정이 이미지에만 있음 | 이미지 판독 포함, 실패 시 "확인 필요"로 분리 |
| 날짜 오해석 (요일·상대 날짜) | 게시 시각 기준 해석 + 추출 결과의 요일과 실제 요일 불일치 시 확인 필요로 분류 |
| 광고·공구 글 범람 | 기본 제외, 계정 차단 목록, 관련도 점수 하한 |
| 토큰 만료로 조용히 멈춤 | 주기적 갱신 + 실행 실패/0건 연속 시 텔레그램 경고 |

---

## 9. 결정이 필요한 것

- 브리핑 시각과 횟수 (예: 08:00 / 20:00)
- 긴급 알림 사용 여부
- 공구·특가 포함 여부
- 받는 대상: 개인 채팅 vs 가족 그룹
- 운영: GitHub Actions(무료, 권장) vs VPS
